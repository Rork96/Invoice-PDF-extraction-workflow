# Invoice PDF → Google Sheet (n8n + LLM, with validation)

n8n workflow that watches a Google Drive folder, extracts text from invoice PDFs, asks an LLM for strict JSON, **validates the result in code**, and routes it:

- valid → `Invoices` sheet, file moved to *Processed*
- anything suspicious → `Needs_review` sheet + Telegram alert, file moved to *Needs review*

The LLM is not trusted. Every extracted value is checked by deterministic code before it reaches the sheet.

> The 40 s explainer (`docs/showcase/explainer.html`) shows the same counts as `eval/eval.json` (files, fields, routing); regenerate it by hand if the eval changes.
>
> All data is synthetic (fictional vendors, generated PDFs). No client data.

## Flow

```
Drive Trigger → Download → Extract text → Preprocess → LLM (JSON only, null instead of guessing)
   → Parse & Validate ──ok──→ Sheets: Invoices ─→ move to Processed
                      └─fail─→ Sheets: Needs_review → Telegram alert → move to Needs review
LLM call fails (after 3 retries) → Needs_review (LLM_CALL_FAILED)
```

## Validation rules (`app/code/validate.js`)

| Rule | Failure code |
|---|---|
| Output must be valid JSON with all schema keys | `JSON_PARSE_FAILED`, `SCHEMA_KEYS_MISSING` |
| Required fields present (no "N/A" placeholders) | `MISSING_INVOICE_NUMBER`, … |
| ISO dates, currency in allowlist (USD/CAD/EUR) | `BAD_ISSUE_DATE`, `CURRENCY_NOT_ALLOWED` |
| subtotal + tax = total (integer cents, ±0.01) | `TOTAL_MISMATCH` |
| qty × unit price = line amount; Σ lines = subtotal | `LINE_n_AMOUNT_NE_QTY_X_PRICE`, `LINES_SUM_NE_SUBTOTAL` |
| Grounding: invoice number, subtotal, total, tax must literally appear in the PDF text | `NOT_IN_SOURCE_*` |

The synthetic set contains two deliberate problem files: `invoice_05` (printed total ≠ subtotal + tax) and `invoice_08` (no invoice number). Both must land in `Needs_review`.

## Run it

```bash
make setup      # needs node, python3, poppler-utils (pdftotext)
make demo       # MOCK mode, zero API keys: replay recorded LLM outputs through the real validator
make eval       # demo + compare committed live n8n export to ground truth → eval/eval.json, eval/eval_live.json
make test       # validator tests → eval/tests.json
make showcase   # regenerate docs/showcase/results.md and the results block above
make live       # real LLM run, needs ANTHROPIC_API_KEY (see .env.example)
```

n8n: `docker compose up`, import `app/workflow/invoice-intake.workflow.json` and `invoice-intake-error.workflow.json`, create credentials in the UI (Google Drive, Google Sheets, LLM, Telegram), replace every `REPLACE_*` value (folder IDs, spreadsheet ID, Telegram chat ID). Sheets need tabs `Invoices` and `Needs_review` with the headers from `docs/showcase/design.md`.

## Limitations

- Free-tier LLM keys hit rate limits (429) during live runs; the workflow retries 3× and then routes to `Needs_review`. Use a paid key for real volume.
- Drive Trigger polls every minute and fires only for newly created files. Manual "Execute workflow" processes only the latest file.
- Scanned PDFs without a text layer go to `Needs_review` (`NO_TEXT_LAYER`); no OCR.
- Duplicate detection: a `dedupe_key` column is written, but no duplicate check is implemented.
- Exact-match grounding can false-flag values the PDF prints in an unusual number format.
- Dataset is tiny and synthetic. Accuracy on real-world invoice layouts is unmeasured.
